# AICam ESP32

The ESP32-S3 runs CircuitPython, joins Wi-Fi, and exposes HTTP interfaces for
manual and [H618](../aicam_h618/README.md) lane control. This module follows the
device filesystem layout without an `app/var` split.

## Firmware baseline

[firmware.toml](firmware.toml) records the restoration baseline:

| Setting | Value |
| --- | --- |
| Board ID | `espressif_esp32s3_devkitc_1_n8r8` |
| CircuitPython | `10.2.1` |
| Firmware build date | `2026-05-13` |

Restore matching board firmware and compatible `.mpy` libraries. Git stores
the version record and required `lib/` files, not the firmware image.

## File roles

| Path | Purpose |
| --- | --- |
| `boot.py` | Disables USB storage for the current wireless workflow |
| `code.py` | Starts `robot_lane_tracking.robot_app.run()` |
| `robot_lane_tracking/` | Wi-Fi server, HTTP routes, and motor control |
| `lib/` | CircuitPython application libraries |
| `settings.example.toml` | Wi-Fi and web workflow configuration template |
| `settings.toml` (ignored) | Actual device settings and credentials |
| `test/` | Earlier experiments and hardware checks |

`boot_out.txt` is generated by CircuitPython and ignored. Use the firmware
record to identify the expected baseline.

## Restore and deploy

1. Install firmware matching `firmware.toml` if the device needs restoring.
2. Copy `settings.example.toml` to `settings.toml` locally and set the Wi-Fi SSID,
   password, web API password, and hostname.
3. Provision Wi-Fi/web workflow through the available initial connection before
   relying on wireless file updates.
4. Upload `lib/`, `robot_lane_tracking/`, `code.py`, `boot.py`, and the actual
   `settings.toml` to the CircuitPython root with the wireless development tool.
5. Reload the application, inspect the console, and verify connectivity.

`README.md`, `firmware.toml`, and `settings.example.toml` are documentation and
templates, not startup dependencies. Deploy `test/` and `sd/` when needed.
Preserve device settings and generated metadata with tools that delete
destination-only files. The current `boot.py` disables USB storage, so restore
Wi-Fi configuration and access before relying on wireless-only updates.

## HTTP interface

`robot_app.py` starts the server and motor loop:

| Route | Purpose |
| --- | --- |
| `/` | Browser keyboard control page |
| `/cmd?m=LEFT` | Manual action; also accepts `RIGHT`, `STRAIGHT`, and `STOP` |
| `/lane?m=LEFT` | Lane decision from H618 |
| `/estop` | Emergency stop |
| `/arm` | Re-arm the motor controller |

The application prints a URL with port 5000, but `sta_server.py` calls
`server.start(bind_ip)` without specifying a port. Verify the actual listening
port before configuring the H618 `--motor-url` or laptop recorder URL.

## Development checks

Edit locally, upload runtime changes, and inspect the device console. Check
Wi-Fi, the browser page, and motor wiring/control before testing lane commands.
Motor pins and tuning are in `robot_lane_tracking/motor_control.py`.

Commit code, libraries, and configuration examples. Actual credentials stay in
the ignored `settings.toml`; fill those in again after a fresh clone.
